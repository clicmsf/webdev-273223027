# Exercise 3 architecture - agent-written review draft

A reservation starts in the view `public/events.html`. `public/events-client.mjs`
keeps the event and current-user reservation snapshots in its `state` object. Its
`request()` helper sends REST requests; the reserve button posts `{eventId}` to
`/api/registrations`. Rendering uses DOM textContent, including server/model text.
The screen disables actions while loading, renders a useful empty message and
shows a readable error with retry if a request fails.

`src/routes/http.mjs` resolves the session using `src/services/auth.mjs`, rejects an
anonymous caller with 401, decodes JSON and calls `reservePlace(db,user.id,eventId)`
in `src/services/registrations.mjs`. The route holds no capacity/ownership rule.
The service checks identifiers, event existence/date, duplicate membership and
capacity. It uses `transaction()` in `src/data/db.mjs`: BEGIN IMMEDIATE encloses the
check and insert, so another database connection cannot claim that final place
between them. All SQL lives in that data module. `migrations/002_registrations.sql`
adds foreign keys and uniqueness for member/event pairs.

The service returns a registration object `{id,user_id,event_id,created_at}`.
The route wraps it as `{registration}` with 201. Domain failures carry stable names
and map to 409, 404 or 422. `cancelReservation()` checks ownership in the service;
another signed-in member receives 403, an anonymous HTTP caller receives 401.
A successful cancellation returns 204; reloading events recomputes availability.

`mcp-server/server.js` resolves CLUB_SESSION_TOKEN with the same authentication
service, then enters at `reservePlace`, `myRegistrations` or `listUpcomingEvents`,
not at an HTTP handler. A caller cannot choose another user id. The two original
lecture tools remain. `src/services/poster.mjs` isolates Gemini, timeout and
manual-entry fallback; suggestions are validated against VENUES and strict future
UTC dates, displayed as editable drafts and never persisted automatically.

Deliberate layering mismatch: `public/events-client.mjs` combines view rendering,
state and the REST helper in one file. It keeps those functions separate but avoids
a framework/store abstraction for one screen. SQL and application rules remain
outside that file. Database bootstrapping is also called by both transport entry
points; that is composition wiring, not duplicated business logic.
